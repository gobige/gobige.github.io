## 写在前面

今年 4 月那篇《AI agent 初窥》写的是 RAG 调参：向量检索得分 0.88，Re-rank 出来却是 0。7 个月过去，这篇写落地的事——Claude Code 提效、销售 AI 智能体上线。定位先说清楚：我做的是应用层落地，不是造 Agent 平台、也不是调模型。引擎、评测、微调那套不是我的活，我的活是把业务流程、特征数据和外部服务接起来，让智能体在真实业务里跑起来、跑得稳。

## 一、RAG 那坑的后续：阈值不能只看向量分

4 月的结论复盘一下：向量检索的 0.88 是 Vector Store 召回时注入的余弦相似度，Re-rank 阶段 bge-reranker ONNX 模型做 Cross-Attention 重新打分，输出的是未经归一化的 Raw Logit，超长或语义稍偏的文本直接跌成负数（比如 -2.1），低于阈值就被整条删掉，最终输出 0。把 chunk 从 500 字符缩到 200 字符确实有效：噪音少了，相关性评分倾向变高，也避开了 512 max_seq_length 的截断。

落地时多补了一条：**上线前先离线跑一批真实 query，看 reranker 原始分的分布再定阈值**，别凭感觉拍一个数。向量分好看不等于 reranker 分好看，两个分数不是一个量纲，混着用阈值一定会误杀。

## 二、Claude Code 提效：提效要落在检查清单上

Claude Code 用了近一年，最大的体会是：提效不是让它多写代码，而是把“人必须检查什么”固定下来。我的清单就三条：

- diff 必须人审，接口契约、边界条件、异常分支不能只看它说“已处理”；
- 改完必须跑测试，测试没覆盖到的分支，提效等于埋雷；
- 涉及资金、授信这类业务动作的链路，改动要能讲清影响面，不能只讲“功能通了”。

工具换代很快，清单比工具活得久。

## 三、销售 AI 智能体落地：应用层的活是“接起来”

销售智能体上线，最难的不是模型选型，是把几样东西接成一条能验收的链路：业务流程怎么走、特征数据从哪来、外部核验服务怎么调、答不上来时人工怎么兜底。我的位置一直是业务接入与特征数据侧：特征加工平台是我做的，加工出的字段喂给专业引擎做判断；规则引擎、决策链路那套核心自建不是我的活，写的时候不揽。

上线验收我只认三条，缺一条就不算落地：

- 业务能验收：回答准不准、拒答率、转人工比例；
- 出问题能定位：每一步调用、每次特征取值都要留痕，复盘时能还原现场；
- 能回滚：智能体出问题时，业务能立刻切回原流程，而不是等修好。

## 结尾：给后来者三句话

1. 先分清自己在应用层还是引擎层，两边的坑不一样，别互相揽活。
2. 阈值、chunk 大小这类参数，上线前用真实 query 的分数分布定，别凭感觉。
3. 落地以“业务能验收、能定位、能回滚”为标准，demo 跑通不算落地。
